# Adjoint Wilson spectral flow

`spectral_flow` is a direct adaptation of
`Grid/tests/lanczos/Test_wilson_specflow.cc`. It retains the original calculation:

```cpp
MdagMLinearOperator<FermionOp,FermionField> HermOp(WilsonOperator);
Gamma5HermitianLinearOperator<FermionOp,FermionField> HermOp2(WilsonOperator);
Chebyshev<FermionField> Cheby(p.ChebyLow,p.ChebyHigh,p.ChebyOrder);
FunctionHermOp<FermionField> OpCheby(Cheby,HermOp);
PlainHermOp<FermionField> Op2(HermOp2);
ImplicitlyRestartedLanczos<FermionField> IRL(OpCheby,Op2,Nstop,Nk,Nm,resid,MaxIt);
IRL.calc(eval,evec,src,Nconv);
```

There is no custom eigensolver, extra signed subspace diagonalization, or CSV
output. As in the original, the calculation filters D_W dagger D_W and uses
H_W = gamma5 D_W for eigenvalue reconstruction and convergence checks. It prints
the eigenvalues and real/imaginary parts of chirality to standard output.

The adaptations are adjoint fermions/links, an XML filename supplied on the
command line, a saved-configuration loop, and XML control of the scan and
Lanczos parameters. Unused objects and dead assignments from the original test
are omitted. The original Grid eigensolver's behavior and limitations are retained;
this adaptation does not independently resolve its degeneracy/convergence issues.

## Build

```sh
./bootstrap.sh
mkdir -p build
cd build
../configure --with-grid=/path/to/Grid/install
make -j2
```

The application uses Grid's SU adjoint types directly (`WilsonAdjFermionD`
and `AdjointRepresentation`); use an Nc=2 Grid installation for SU(2).
Nc and MPI/SIMD/backend choices come from your installed Grid. If `grid-config`
is already on PATH, simply run `../configure`.
If required by your Homebrew Grid installation, add
`CPPFLAGS=-I/opt/homebrew/opt/openssl@3/include` to the configure command.

## Input and run

Edit `par-example.xml`, then from `build` run:

```sh
./spectral_flow ../par-example.xml --grid 16.16.16.32 --mpi 1.1.1.1 > spectral-flow.log 2>&1
```

Match the lattice dimensions to your files and use your usual MPI launcher for
an MPI-enabled Grid build. The executable reads NERSC gauge files named
`cfg_prefix.NUMBER`, for cfg_start through cfg_end in increments of cfg_step.
These can be configurations generated by domain-wall or Möbius simulations.
The gauge group, Nc, boundary conditions, and thin-link kernel must match the
measurement you intend. No gauge flow or smearing is applied.

XML parameters:

- `M5_start`, `M5_end`, `M5_step`: ascending scan, Wilson mass = **-M5**.
  The endpoint is included if it lies on the step sequence.
- `Nstop`, `Nk`, `Np`, `MaxIt`, `resid`: the original Grid IRL parameters;
  maximum basis size is `Nm = Nk + Np`.
- `ChebyLow`, `ChebyHigh`, `ChebyOrder`: original Chebyshev constructor arguments,
  applied to D_W dagger D_W. Order means degree + 1 in this Grid implementation.
  The example filter settings are starting values, not automatically tuned.
- `boundary_conditions`: four `<elem>` entries in x,y,z,t order, +1 periodic
  or -1 antiperiodic. All periodic reproduces the original test's default.
- `rng_seeds`: Grid RNG seed vector. The example reproduces the original seeds.

For each scan point the log includes a configuration/M5/mass/Nconv label, then
the original `mass : eigenvalue real(chirality) imag(chirality)` lines. There is
no automatic classification of an M5 value as safe.
